# Module 09 PPT | Capstone Studio

**README duration:** 24 h | **Build thread:** teams solve a campus/community problem | **Evidence:** working project, repo, docs, deployment, presentation

## Slide sequence

1. **Choose a problem worth solving** (10 min) — Identify a real user and friction; avoid “build an app” as the problem statement.
2. **Constrain the first release** (15 min) — User story, acceptance criteria, must-have vs later; choose a demonstrable vertical slice.
3. **Design before parallel coding** (15 min) — Wireframe, API contract, data model, trust boundaries, task ownership.
4. **Build in short checkpoints** (15 min) — Branches, integration points, daily demo, test evidence, blockers.
5. **Review and improve** (15 min) — Peer review, edge cases, accessibility, security, error states, performance only where measured.
6. **Deploy and tell the story** (15 min) — Live verification, architecture explanation, user journey, trade-offs, limits, next step.
7. **Team commitment** (10 min) — Run Demo 09 kickoff, then Lab 09. Exit: each member names a deliverable and reviewer.

## Instructor cues

Use the README's suggested capstones as options. A modest, complete vertical slice beats an ambitious unfinished feature list. Hold regular mentor checkpoints; grade individual understanding as well as team output. Require fictional/sample data in public demos.
