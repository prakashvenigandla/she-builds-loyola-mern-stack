# Module 02 PPT | HTML, CSS and JavaScript

**README duration:** 10 h | **Build thread:** event card + accessible registration form | **Evidence:** responsive page with validated interaction

## Slide sequence

1. **Design for a real attendee** (5 min) — What must a student know before registering? Capture title, date, venue, and capacity.
2. **HTML gives meaning** (15 min) — Semantic landmarks, headings, buttons, forms, labels; compare a real button with a clickable `div`.
3. **CSS shapes the experience** (20 min) — Box model, readable spacing, Flexbox/Grid; inspect a card at phone and desktop widths.
4. **Responsive is a behavior** (15 min) — Content-first layout, media queries, keyboard focus and contrast. Avoid “desktop shrunk to phone”.
5. **JavaScript responds to people** (20 min) — Variables, functions, DOM selection, events; show submit → validate → feedback.
6. **Forms should help, not trap** (15 min) — Labels, required fields, helpful errors, success state, and accessible focus.
7. **Build and inspect** (10 min) — Run Demo 02, then Lab 02. Ask: can a keyboard-only user register?

## Instructor cues

Start from the user task, not a gallery of CSS properties. Show invalid and valid form submissions. Use browser responsive mode and keyboard tabbing. Keep personal portfolio assignment as take-home; this module's in-class artifact is the smaller event registration flow.
