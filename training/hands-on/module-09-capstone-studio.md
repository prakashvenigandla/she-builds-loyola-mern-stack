# Module 09 Lab | Capstone Studio

**Pair with:** PPT 09 slides 2–6 and Demo 09 | **Suggested time:** full 24 hours in mentor-guided studio blocks

## Challenge

Teams select one README capstone or propose a comparable problem. Deliver a working, deployed MVP with a clear user journey. Every member must own and explain a contribution.

## Checkpoints

1. **Problem:** user, pain point, evidence, scope, and three measurable acceptance criteria.
2. **Design:** low-fidelity screens, architecture/data sketch, API contract, risk/privacy note, task board.
3. **Build:** working vertical slice, small reviewed changes, integration demo, test record.
4. **Verify:** happy path, failure path, responsive/accessibility check, no secrets or real private data.
5. **Release:** deployment URL, smoke-test evidence, known limitations, recovery plan.
6. **Present:** 5-minute user journey, architecture, one trade-off, individual contribution, next iteration.

## Acceptance checks

- A new user can complete the MVP's primary journey in the deployed build.
- Repository runs from documented steps; no secrets are committed.
- Team shows tests or explicit manual checks for acceptance criteria.
- Each student explains their own change and one system boundary.

**Extension:** add a second user role or measured usage feedback. **Evidence:** repo, deployment, concise technical documentation, demo deck, and individual reflection.
